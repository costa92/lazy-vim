# 代码诊断和质量检查快捷键指南

本文档详细介绍了所有与代码质量检查、错误诊断和 LSP 功能相关的快捷键。

## LSP 核心功能

### 代码导航
| 快捷键 | 功能描述 |
|--------|----------|
| `gd` | 跳转到定义 |
| `gr` | 查看引用 |
| `gi` | 跳转到实现 |
| `<leader>D` | 跳转到类型定义 |
| `K` | 显示悬浮文档/帮助信息 |

### 代码操作
| 快捷键 | 功能描述 |
|--------|----------|
| `<leader>rn` | 重命名符号 |
| `<leader>ca` | 显示代码操作菜单 |
| `<leader>i` | 格式化当前文件 |

## 诊断导航

### 快速导航
| 快捷键 | 功能描述 |
|--------|----------|
| `[d` | 跳转到上一个诊断 |
| `]d` | 跳转到下一个诊断 |

### 诊断显示
| 快捷键 | 功能描述 |
|--------|----------|
| `<leader>e` | 显示当前行诊断（浮动窗口） |
| `<leader>q` | 打开诊断 quickfix 列表 |

## 代码质量检查

### 手动检测
| 快捷键 | 功能描述 |
|--------|----------|
| `<leader>l` | 手动运行代码检测（Lint） |

### 命令
| 命令 | 功能描述 |
|------|----------|
| `:Lint` | 手动运行当前缓冲区的代码检测 |
| `:Mason` | 打开 Mason 工具管理界面 |

## Trouble 诊断界面

### 主要界面
| 快捷键 | 功能描述 |
|--------|----------|
| `<leader>xx` | 打开/关闭 Trouble 诊断界面 |
| `<leader>xX` | 显示当前缓冲区诊断 |

### 专项功能
| 快捷键 | 功能描述 |
|--------|----------|
| `<leader>cs` | 显示符号列表（Trouble） |
| `<leader>cl` | 显示 LSP 定义/引用（Trouble） |
| `<leader>xL` | 位置列表（Trouble） |
| `<leader>xQ` | Quickfix 列表（Trouble） |

## 自动化功能

### 自动检测触发条件
- **文件保存时**：自动运行相应语言的 linter
- **进入缓冲区时**：检查文件是否需要 lint
- **退出插入模式时**：触发代码质量检查

### 支持的检测工具
| 语言 | 检测工具 | 功能 |
|------|----------|------|
| Go | golangci-lint | 代码质量、性能、安全检查 |
| Shell | shellcheck | 脚本安全和最佳实践 |
| YAML | yamllint | 语法和格式检查 |
| JSON | jsonlint | JSON 格式验证 |
| Lua | luacheck | 语法和风格检查 |
| Markdown | markdownlint | 文档格式和风格 |
| Dockerfile | hadolint | Docker 最佳实践 |

## 诊断标识说明

### 符号含义
| 符号 | 含义 |
|------|------|
| ✘ | 错误（Error） |
| ▲ | 警告（Warning） |
| ⚑ | 提示（Hint） |
| » | 信息（Info） |

## 使用技巧

### 日常工作流程
1. **编写代码**：正常编码
2. **实时反馈**：保存时自动检测问题
3. **快速导航**：使用 `[d` / `]d` 在问题间跳转
4. **查看详情**：`<leader>e` 查看详细错误信息
5. **批量查看**：`<leader>xx` 打开 Trouble 界面统一处理

### 高效排错
1. **优先级处理**：错误 > 警告 > 提示 > 信息
2. **批量修复**：`<leader>ca` 查看可用的自动修复
3. **手动检测**：`<leader>l` 强制重新检测
4. **工具管理**：`:Mason` 安装/更新检测工具

### 搜索调试
- 使用 `<leader>fs` 快速定位函数和变量
- `<leader>fr` 查看某个函数的所有使用位置
- `<leader>fd` 找到符号的定义位置

## 常见场景

### Go 开发
```
1. 编写代码 → 保存时自动运行 golangci-lint
2. 发现问题 → 使用 [d/]d 导航到错误位置
3. 查看详情 → <leader>e 显示具体错误信息
4. 修复代码 → <leader>ca 查看可用修复建议
```

### 配置文件编辑
```
1. 编辑 YAML/JSON → yamllint/jsonlint 自动检测
2. 格式问题 → 实时显示格式错误
3. 批量查看 → <leader>xx 统一处理所有问题
```

### 脚本开发
```
1. 编写 Shell 脚本 → shellcheck 检测安全问题
2. 最佳实践 → 自动提示更好的写法
3. 问题修复 → 根据建议改进代码
```

## 配置自定义

### 添加新的 Linter
1. 在 `lua/plugins/nvim-lint.lua` 中添加配置
2. 更新 Mason 确保工具自动安装
3. 重启 Neovim 生效

### 调整检测频率
- 修改 autocmd 触发条件
- 可以设置为仅保存时检测以提升性能

## 故障排除

### 常见问题
- **Linter 未运行**：检查 `:Mason` 中工具是否已安装
- **诊断不显示**：确认文件类型是否在支持列表中
- **性能问题**：可临时禁用某些检测工具

### 调试命令
- `:checkhealth` - 检查 Neovim 健康状态
- `:LspInfo` - 查看 LSP 客户端状态
- `:Mason` - 管理检测工具安装
