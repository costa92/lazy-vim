# Neovim Git 快捷键指南

本文档列出了所有与 Git 操作相关的快捷键命令。

## Git 行状态显示 (Gitsigns)

### 状态标记说明

在行号左侧会显示 Git 状态标记：

| 标记 | 含义 |
|------|------|
| `│` | 该行已修改（绿色） |
| `│` | 该行已添加（绿色） |
| `_` | 该行已删除（红色） |
| `~` | 该行有修改和删除（黄色） |
| `┆` | 未跟踪的新文件（蓝色） |

### 切换显示快捷键

| 快捷键 | 功能描述 |
|--------|----------|
| `<space>tg` | 切换显示/隐藏 Git 状态标记 |
| `<space>tb` | 切换显示/隐藏当前行的 Git blame 信息 |
| `<space>td` | 切换显示/隐藏已删除的行 |

## Git Hunk 导航

| 快捷键 | 功能描述 |
|--------|----------|
| `]c` | 跳转到下一个修改处（hunk） |
| `[c` | 跳转到上一个修改处（hunk） |

## Git Hunk 操作

### 预览和查看

| 快捷键 | 功能描述 |
|--------|----------|
| `<space>hp` | 预览当前修改（在浮动窗口中显示） |
| `<space>hb` | 显示当前行的完整 Git blame 信息 |
| `<space>hd` | 显示当前文件的 diff |

### 暂存和重置

| 快捷键 | 功能描述 |
|--------|----------|
| `<space>hs` | 暂存当前 hunk (stage) |
| `<space>hr` | 重置当前 hunk (reset) |
| `<space>hS` | 暂存整个文件 |
| `<space>hR` | 重置整个文件 |
| `<space>hu` | 撤销暂存的 hunk |

### 可视模式下的操作

| 快捷键 | 功能描述 |
|--------|----------|
| `<space>hs` | 暂存选中的行 |
| `<space>hr` | 重置选中的行 |

## Git 文本对象

| 快捷键 | 功能描述 |
|--------|----------|
| `ih` | 选择当前 hunk（可用于操作符，如 `dih` 删除 hunk） |

## Git 文件操作 (Fugitive)

| 快捷键 | 功能描述 |
|--------|----------|
| `:Git` 或 `:G` | 打开 Git 状态窗口 |
| `:Git blame` | 查看文件的 Git blame |
| `:Git diff` | 查看文件差异 |
| `:Git log` | 查看提交历史 |

## Git Blame 显示 (blame.nvim)

| 快捷键 | 功能描述 |
|--------|----------|
| `<space>b` | 切换显示/隐藏 Git blame 信息 |

## FZF Git 搜索

| 快捷键 | 功能描述 |
|--------|----------|
| `<space>gp` | 搜索 Git commits |
| `<space>gb` | 搜索当前文件的 Git commits |
| `<space>gs` | 搜索 Git 状态（查看修改的文件） |

## 使用场景

### 场景 1：查看当前修改

```
1. 打开文件，左侧会自动显示 Git 状态标记
2. 按 ]c 跳转到下一个修改处
3. 按 <space>hp 预览修改内容
4. 按 <space>hb 查看是谁修改的这行代码
```

### 场景 2：逐个暂存修改

```
1. 按 ]c 跳转到修改处
2. 按 <space>hp 预览修改
3. 如果满意，按 <space>hs 暂存这个修改
4. 重复以上步骤，选择性暂存修改
5. 最后使用 :Git commit 提交
```

### 场景 3：查看历史修改

```
1. 光标放在某一行
2. 按 <space>hb 查看这行代码的提交信息
3. 按 <space>tb 开启实时 blame 显示
4. 移动光标时会自动显示每行的提交信息
```

### 场景 4：重置不需要的修改

```
1. 按 ]c 跳转到修改处
2. 按 <space>hp 预览修改
3. 如果不需要这个修改，按 <space>hr 重置
```

### 场景 5：对比文件差异

```
1. 按 <space>hd 打开 diff 视图
2. 查看完整的文件差异
3. 按 :q 关闭 diff 视图
```

## 工作流程示例

### 完整的代码审查流程

```
1. <space>tg         → 确保 Git 状态标记显示
2. ]c               → 跳到第一个修改
3. <space>hp        → 预览修改内容
4. <space>hb        → 查看修改者和原因
5. ]c               → 继续查看下一个修改
6. 重复步骤 3-5
```

### 选择性提交流程

```
1. ]c               → 跳到修改处
2. <space>hp        → 预览修改
3. <space>hs        → 暂存这个修改
4. ]c               → 下一个修改
5. <space>hr        → 丢弃这个修改
6. 重复，直到处理完所有修改
7. :Git commit      → 提交暂存的修改
```

## 提示

1. **Git 状态标记**：
   - 默认会显示在行号左侧
   - 使用 `<space>tg` 可以切换显示/隐藏
   - 不同颜色表示不同的修改类型

2. **Blame 信息**：
   - 使用 `<space>tb` 开启后会实时显示
   - 显示格式：作者, 日期 - 提交信息
   - 默认延迟 500ms 显示，避免干扰

3. **Hunk 操作**：
   - Hunk 是指一组连续的修改行
   - 可以单独暂存或重置每个 hunk
   - 在可视模式下可以选择部分行操作

4. **性能考虑**：
   - 大文件（> 40000 行）会自动禁用某些功能
   - 使用防抖优化，避免频繁更新
